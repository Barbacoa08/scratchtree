## Scope and current state

Scratchtree is an independent developer-oriented Markdown notes application. Preserve visible editable Markdown with live styling, especially emphasis, code blocks, and lists, and familiar keyboard commands. The accepted stack is SvelteKit static output, Svelte, CodeMirror, Tauri, persistent Dexie IndexedDB, and Dexie Cloud. Keep the framework-neutral controller and typed Repository boundary. Current-only BackupV8 has format `scratchtree`, a shared `library` of items/purge facts, and device-local drafts, ordered Undo, and recovery. Unsupported formats are rejected rather than converted in the product; there is no SQLite bridge or legacy reader.

The current source is a local-first Mac alpha with private existing-account synchronization, a unified source-bearing Item tree, nested trees, global saved-source search, explicit capture, 300 ms debounced existing-item saves, scoped draft checkpoints, persistent completion, retained Trash trees, one-step Undo, and backup export/restore. Follow the release guide to verify Developer ID signing and notarization for each public Apple Silicon DMG. Apple Silicon 0.3.2 is the first public Mac build configured for in-app update checks. Users install its notarized DMG once to receive newer offers. The Arch Linux Preview uses a manual package. Mobile and public sign-up remain future work. The retained alpha.5 installer is local-only. Describe the exact downloaded version and do not imply public sign-up. Authorization comes from the current task and applicable user instructions, not historical branch names or approvals. Do not merge, publish, use signing credentials, or operate accounts/services without applicable authorization; when the user has already authorized the action, complete it without asking again. Dedicated editable Trash navigation and Restore controls are implemented. Fixed color selection, mouse multi-selection, sibling rearrangement, and the M destination dialog are implemented. Palette controls have accessible color names and saved-state checks. One latest-input-owned tooltip shows the hex value and color name outside the matching swatch column. The nonmodal color picker uses a two-column button layout grid: arrows stage, saved pressed/check state stays distinct, and Enter/Space/click applies once and closes after acknowledgment. Pending dismissal never cancels the captured write or blocks external focus. Failed dismissal retains the exact session/item/color Retry context; older completion cannot close a newer picker or reclaim newer focus. Independent review and packaged native acceptance remain separate gates.

The experimental Arch Linux x86_64 Preview uses a pacman package and the ordinary Preview identity. It uses the Linux window manager’s controls and Ctrl shortcuts. Closing its window flushes pending work before exit. A failed flush keeps the window open for retry or continued editing. Current evidence covers signed-out local use with virtual X11 and Arch WebKitGTK. Preserve those evidence limits in release guidance.

The editor uses per-location composers and one reusable source-bearing card for either kind. Empty destinations focus capture; nonempty destinations restore the last valid selection or select the first entry with stream focus. Command-N enters the valid selected visible item, including an inline edit or search result, and focuses capture without inserting a child. With no selection it focuses the current composer, like Space. Command-2–9 opens the first eight sidebar-visible direct Root trees in sibling order; completed trees and their descendants are excluded from sidebar navigation. Blank stream background safely clears selection after flushing, while composer Escape retains the previous highlight. There is no Rename dialog or separate name field. Sidebar labels are bounded first-line source previews. Search includes live container source, excludes inherited Trash, and retains createdAt/exact-ID order independently of manual sibling ranks. X toggles either selected kind with the existing typing, selection, composition, modifier, and repeat guards; the Mark done action keeps a stable accessible name, pressed state, and next-action tooltip.

The overlay title strip retains native decorations/traffic lights, hides native title text, reserves native-only control space, and matches the sidebar background. Only blank authored surfaces are drag regions; controls are excluded. Session history holds up to 100 successful exact scope/item visits. Back/Forward and bounded root/last-two-ancestor breadcrumbs use openLocation without promotion, skip stale recorded scopes, retain failed traversal until successful Retry, and invalidate it on newer navigation. Structural moves reconcile the current entry; full replacement resets history. Observe location patches synchronously rather than inferring operation causes from coalesced view effects. Root and Trash roots remain distinct visits. Root replaces the previous Home destination label throughout current navigation, accessible names, shortcuts, move paths, and restore explanations. Keep physical Home/End key names and stored user source unchanged. The small monochrome Flowing Roots icon and nonfocusable separator precede child navigation; Root never collapses. Dock assets are generated from the selected reference family, while other functional icons stay unchanged. Details toggles at every width, frees its wide column when hidden, and preserves an explicit session choice across breakpoints; responsive defaults apply only before that choice. Outside fenced code, Enter finishes inline editing and keeps changes; Escape finishes editing from any position and keeps changes. Inside fenced code, Enter, Shift+Enter, and Command+Enter insert code lines, including on delimiters. Failed persistence retains source, blocks the transition, and retains the command's own captured retry intent. Capture Up at offset zero with one empty caret returns focus to the highlighted visible item, falling back to the last visible note only when no valid highlight exists, and preserves draft, caret, history, and search. When no entries are displayed, Up or Left at that same boundary focuses the stream, as Escape does, so another Left can open the parent. Left in a nonempty stream and Up in a tree-only stream without a highlight retain ordinary editor behavior. Inline editing preserves its rendered entry footprint, grows after source changes, and retains its geometry, caret, and history across autosave; only the body or active editor owns vertical scrolling. Buffers, composer keys, and editor histories stay attached to exact item IDs through promotion, deletion, and restoration. Only successful full backup replacement resets all editor caches; an acknowledged permanent purge prunes only removed item/composer keys.

Delete a live item without confirmation into Trash, remembering its owner/ordinal and retaining the parent-edge tree. Capture the target, exact scope, and subtree before awaits, reject stale membership or a now-live target, and prune exact buffers, editor histories, and pending intents only after acknowledgment. Clear dangling restore pointers while retaining applicable ordinals; remove only purged IDs from the pending Undo group. Keep the same-ordinal successor, otherwise previous item, otherwise composer focus. Editor and Search Undo and Shift-Command-Z keep their existing behavior. Trash has a scoped composer/search and editable trees; retained items have no automatic permanent cleanup timer. The 90-day minimum retention policy excludes a user's explicit permanent deletion. Restore uses a remembered live owner (promoting an empty note if needed), otherwise Root, and a clamped ordinal. Nested independent deletion records stay deleted when an ancestor restores, by detaching them as Trash roots. One persistent ordered Undo group references explicit deletion records and survives unrelated restoration or purge. Live Delete or M into Trash installs all captured roots as one ordered Undo action. Group purge in Trash verifies the captured roots, sibling location, and exact parent-edge subtree membership before removing the entire group. Restore and purge remove only matching members, preserving the remaining order. Undo restores the captured remaining group in one transaction, using each item's remembered owner and ordinal, with the existing Root fallback. A failure restores none and consumes none. All creation intents keep one exact UUID through reconciliation/retry; never regenerate or resurrect a purged creation.

Validate the full prospective current envelope before every commit/import: 20,000 items, 40,002 drafts, 1 MiB UTF-8 per source, and a 10 MiB complete compact backup ceiling. ## Working process

- Read [README.md](README.md), this guide, current maintenance/test guidance when present, and the active task's local status. A fresh clone must remain usable without private scratch notes.
- Start new source or maintained-guidance changes from freshly fetched, verified `origin/main` in an isolated task worktree unless Joe authorizes continuation or a different base. Preserve unrelated work.
- Use `.projects/YYYY-MM-DD-short-task-name/` for research, designs, plans, checklists, reviews, logs, screenshots, and comparisons, following [.projects/README.md](.projects/README.md). This overrides default skill locations for committed planning and verification reports.
- Maintain `status.md` with scope, state, decisions, open questions, related PR, and retention instructions. Distinguish accepted requirements, direct observations, and proposals.
- Keep source, reusable synthetic tests, lockfiles, configuration, and concise current guidance in Git. Keep temporary execution history out of Git.
- Preserve active follow-ups before retiring a worktree. Inspect ignored material, verify any necessary transfers, and delete only task-owned disposable material. Do not blanket-delete scratch directories or use `git clean -fdx`.
- Summarize changed behavior, actual verification, and material limits in the PR. Merge, publication, signing, distribution, and new service/account operations remain separate actions requiring applicable authorization.

## Product and code quality

- Prioritize accurate Markdown editing and predictable keyboard interaction. Define formatting, submission, navigation, selection, focus, and undo behavior explicitly.
- Keep responsibilities clear between note/tree rules, editing, commands, persistence, and platform integrations. Centralize shared policy and avoid speculative infrastructure.
- Preserve unsaved and saved work through errors, migrations, and updates. Use isolated test stores and verify recovery before real-data migration.
- Use meaningful regression tests for behavior changes, including Markdown fidelity, keyboard focus, hierarchy, persistence, and recovery. Use proportionate content/link/ignore/diff checks for documentation-only changes.
- Record the source/build identity, environment, results, omissions, and evidence limits. Screenshots establish appearance; browser tests, desktop tests, assistive-technology checks, and physical-device acceptance establish different things.
- Agree on independent review scope before implementing an increment. Use separate fresh reviewers for required independent roles; primary self-review does not replace them. Save reports locally and resolve material findings before integration.
- Use independent subagents for those reviews. Behavior changes require separate correctness/specification and maintainability/extensibility reviews, plus relevant visual, interaction, and accessibility review for UI changes. Documentation-only changes use one fresh independent review and proportionate checks. Follow [CONTRIBUTING.md](CONTRIBUTING.md) for review timing, final-source identity, and when a scoped follow-up is warranted; do not repeat completed review panels without cause.
- Use approved original-app observations as interaction and appearance references, without copying proprietary code/assets or private captures. Prefer simple locally authored CSS and vector icons. No desktop styling library is selected; adding one needs a concrete maintenance benefit and applicable authorization. The separate landing page uses `@barbajoe/css-lib`.

# Scratchtree

Scratchtree is a local-first Mac notes app for developers. Capture a thought without leaving the keyboard, write Markdown with its syntax still visible, and keep code snippets, lists, and related notes together in note trees.

Scratchtree is an independent, developer-focused Markdown notes app, inspired by Stashpad Lists. This is an early alpha for Apple Silicon Macs. The current source adds private, existing-account Dexie Cloud synchronization while keeping notes available locally. Public sign-up is not available. The published download below remains the earlier local-only alpha.5.

## Download and install

**Scratchtree alpha:** the application has its own name, native identity, note-tree terminology, and backup format. The Mac app keeps running when its window closes and returns through Command+Tab or the Dock.

**Alpha compatibility:** the published alpha.5 uses SQLite and BackupV7. Current source uses persistent Dexie IndexedDB and BackupV8, starts a separate empty library, and never automatically reads the old store. Before testing the new source with existing notes, export an unchanged backup from alpha.5, convert a copy with the separate local transfer tool, and verify its import and fresh export. Keep the original backup and recovery installer. Breaking changes are expected during alpha.

[Download Scratchtree v0.1.0-alpha.5 for Apple Silicon](https://github.com/Barbacoa08/scratchtree/releases/download/v0.1.0-alpha.5/Scratchtree_0.1.0-alpha.5_aarch64.dmg) · [Release notes](https://github.com/Barbacoa08/scratchtree/releases/tag/v0.1.0-alpha.5)

1. Export a backup before updating, and quit older app copies. The published alpha.5 uses a different backup format: prepare a converted BackupV8 copy before importing it into the current source build. See the backup transfer instructions below.
2. Open the downloaded DMG, drag Scratchtree to Applications, and replace the existing app if prompted. Your app data is stored separately from the app.
3. Open Scratchtree from Applications. This alpha is ad-hoc signed, but is not Developer ID signed or notarized, so macOS may block the first launch.
4. If macOS shows a warning, click **Done**. Open **System Settings → Privacy & Security**, scroll to **Security**, and click **Open Anyway** for Scratchtree.
5. Authenticate if prompted, and confirm **Open**.

Only open the app if you trust the download. A managed Mac may restrict this option. See [Apple’s instructions for safely opening apps](https://support.apple.com/en-us/102445) for more information.

## Get started

- Type a note in the bottom composer and press Enter to save. Markdown markers stay visible while emphasis, lists, and code are styled.
- Select a note and press E or double-click to edit it. Press Enter outside fenced code or Escape to finish editing and keep changes.
- Press Command+N to create a child tree, or Enter/Right on a selected item to open it. Use the breadcrumb, Back/Forward controls, or mouse side buttons to navigate.
- Press Command+F to search and X to toggle completion. Command-click adds/removes selections; Shift-click selects a range. Drag or Command+Up/Down rearranges selected siblings, and M opens the move destination dialog.
- Export backups from the app to keep a separate copy of your library. Trash retains deleted items and supports restoring them.

The sections below describe the current source. Its stack is SvelteKit static output, Svelte, CodeMirror, Tauri, persistent Dexie IndexedDB, and Dexie Cloud. Native code provides file dialogs, atomic backup files, window behavior, clipboard, and external links. Root is the always-visible top of the live library. Its small tree icon and separator distinguish it from the child trees below; it has no expand/collapse control.

## Appearance

Use the three-part **Appearance** control at the bottom of the sidebar: **Light** (sun), **System** (computer), and **Dark** (moon). System is the default and follows your Mac's appearance, including changes while Scratchtree is open. An explicit choice is remembered on that device. Use Tab to focus the selected option, arrow keys to change it, and Tab to leave the group. Appearance is separate from your note library and backups; changing it keeps unfinished Markdown and editor Undo history. These controls describe current source; the alpha.5 download above predates light mode.

## Capture and edit

Outside fenced code, Enter saves, Shift+Enter adds a line or continues a list, and Command+Enter also saves. Inside a fenced code block, all three insert a code line; move outside the fence to save with Enter, or use Save note. Opening and closing delimiter lines count as code, and an unclosed fence stays code through the end of the source. Empty captures are rejected, and the composer clears only after acknowledgment. Markdown delimiters remain visible while emphasis, all six distinct heading levels, lists, and code are styled. Command+B and Command+I toggle bold and italic on the actual source. A selection stays selected inside the new markers; an empty caret inserts paired markers, or removes its enclosing style when already formatted. Bold and italic combine, and removing one keeps the other. Formatting leaves inline and fenced code unchanged, and ambiguous partial delimiter selections are left untouched. Each command is one Undo step. Standard copy, paste, selection, and undo operate on the actual source. LF, CRLF, and mixed source separators remain intact through edits and undo. New typed line breaks use the existing first separator, or LF when the document has none. Raw paste/input separators are retained when the browser exposes them; OS clipboard conversion remains a platform limit.

Typing the third opening backtick on an otherwise empty plain line, with zero to three leading spaces and one caret at its end, immediately adds a matching closing fence on the next line. A single typed input containing exactly three backticks also works. The caret stays after the opening ticks for language-info typing; Enter then inserts the body line before the closer. The triggering input and generated closer undo and redo atomically, using normal editor history and Redo caret behavior. Consecutive extra backticks extend only that newly generated pair; moving the caret or typing anything else ends that pairing ownership. Existing valid closers, direct inputs of four or more ticks, pasted/dropped text, selected text, multiple carets, composition, read-only input, inline code, existing fenced code, list/quote contexts, and tilde fences receive no automatic pair. Existing source bytes and separators stay intact. The drawn caret retains normal blinking and its full stroke at blank and start-of-line positions inside the editor scrollport.

Single click selects a card. Double click, Edit, or E opens inline editing for either kind of item. E places the caret at the source end every time, including cached edits; pointer editing retains the cached caret. Existing-item edits save after 300 ms idle. Outside fenced code, Enter finishes editing; Escape always finishes editing. Both keep changes and leave the same note selected for immediate E. Clicking away saves and exits while preserving the new target and focus. Navigation flushes the latest visible source. Saved note bodies grow naturally up to 24rem. Overflowing notes expose a full-width Expand/Collapse bar with one trailing directional chevron; expanded bodies grow up to 48rem and then scroll internally. Expansion follows each exact note ID for this editor session and survives promotion, soft deletion, and Undo, and resets after full backup replacement. Inline editing enters at the rendered body’s footprint, including when raw links or fence markers are taller. Changing the source lets the editor grow from that baseline to the current cap, then scroll internally; autosave preserves the grown editor, caret, and history. Emptying an existing note keeps its identity and ownership; deletion is explicit. The shortcut reference retains the selected note’s most recent editing context after finishing, and clears it when selection changes or the library is restored. Root, Trash, and each tree have independent capture drafts and cached editor history. Composer and inline drafts are independent; Escape from the composer preserves its text and the prior highlight, and focuses the stream. Up with one empty caret at source offset zero selects the last visible note, skipping child trees, and focuses the stream while preserving the draft, caret, history, and search query. With no visible note, it keeps ordinary editor focus. Search filters saved source globally and case-insensitively, shows each result’s owning path, keeps the capture destination visible, and labels any active edit outside the results. Sidebar navigation clears search; editing a search result preserves its query and the current capture destination. Search includes saved tree source. Root search excludes effectively deleted trees; Trash search searches only trashed saved source; its created-time/ID order is separate from sibling order.

Command+N creates an Untitled child inside the valid selected visible item, including an inline edit or search result. A selected note becomes a tree atomically with child creation, retaining its exact ID, source, completion, color, parent, and position. With no selection, Command+N uses the current location. The new empty child opens with composer focus. Leaving a tree with no saved children turns it back into a note, preserving its source, identity, and composer draft. Enter/Right can open it again; history skips destinations that are no longer trees. Clicking blank stream background safely flushes an active edit and clears the selection; Escape from the composer preserves the prior highlight. Containers have ordinary source editing, copy, completion, and deletion actions; there is no Rename dialog or separate trimmed name field. Empty existing source remains valid. Sidebar and location labels use bounded source previews, and deep rows retain limited indentation and their actual level.

Space outside controls focuses capture. Command+/ or Command+F focuses search from editors or the stream; / also focuses search outside controls. Command+1 opens Root after flushing the latest source. Hold Command to reveal anchored Search and Root hints without moving content or focus; Escape clears search and focuses the stream. Up/Down selects cards. Enter/Right opens any selected stream item, promoting a note while preserving its identity and source. Empty destinations focus the composer; nonempty destinations restore the last valid selection or select their first entry with stream focus. Left outside controls opens the parent and selects the tree just exited. Double click edits source. X toggles completion for either selected kind without hiding it or changing Markdown. Completed items stay searchable, use subdued strike-through in saved rendering, and remain legible while editing. The Mark done toggle keeps its accessible name, exposes its pressed state, and changes its tooltip to describe the next action. Held X, modifiers, composition, text selection, and typing controls do not toggle completion. E edits at the source end, C copies all selected visible notes in displayed order with one newline between their exact Markdown sources, and Command+Backspace deletes either kind without confirmation. Copy Markdown uses the same group, includes a selected tree’s own source without its children, and uses the active source buffer when applicable. Deletion selects the successor at the same visible ordinal, otherwise the previous item, otherwise the composer. Single-letter shortcuts leave text inputs, selection, composition, and confirmations alone. Copy failure is shown without changing source. M moves selected siblings to an eligible tree, Root, or Trash. Moving from the live library into Trash creates one undoable group; moving back restores the selected items at the chosen destination and keeps independently deleted descendants in Trash.

The unified title strip contains Back/Forward session history and a clickable breadcrumb. Mouse side buttons Back/Forward use that same app history once on release, including over editors; their URL-history default is consumed at boundaries and while blocked. History retains up to 100 acknowledged visits, including distinct Root and Trash roots. A new visit after Back replaces the forward branch; failed navigation does not move the cursor, and a successful captured Retry records or completes its original visit. Missing trees and entries whose recorded live/Trash scope has changed are skipped. Structural deletion/restoration reconciles the current slot, and full backup replacement resets the session history. History and breadcrumb navigation flush source and never promote a note. The breadcrumb shows the scope root, at most the last two source previews, and an omitted-ancestor count for deeper paths; Trash ancestry stops at the explicit deleted root. Left remains available for successive parent navigation within the current scope.

Show/Hide Details works at every width. Before a deliberate choice, Details is shown on wide windows and hidden at 1050px or narrower; a session choice survives later resizing. Collapsing releases the wide column, removes the rail from keyboard and accessibility navigation, and moves focus from its contents to the toggle. Expanding on resize retains Search/editor focus. Editor status and its local-save explanation remain at the bottom of expanded Details. While collapsed, normal status remains announced without occupying space, and actual errors, bounded color context, and captured Retry controls appear in a compact scrollable panel at the lower right. The panel does not change editor geometry. A simultaneous failed palette has separate scroll space so its controls and pointer Retry remain reachable.

L outside typing controls opens Assign color for the selected item; Details also exposes Assign color. The named nonmodal palette contains a two-column layout grid of nine fixed-color swatches and an icon-only Reset. Names remain accessible to assistive technology; no color-name text is shown visually. Arrow keys stage a choice by row and column without changing the saved color; boundaries stop, Home/End move within a row, and the pressed state and check mark identify the saved color. Enter, Space, or clicking applies the exact choice once and closes after acknowledgment. Escape, outside focus/pointer, and Tab dismiss an unsubmitted or failed choice without writing; pending dismissal requests leave the picker visible while external controls remain usable. Failure retains the exact item and color for Retry action, with bounded item context in Editor status. Successful retry only closes its own session and never takes newer Search focus. There is no Done button. Colors affect the note gutter marker, tree icons, and the selected nonediting card border, leaving source text contrast unchanged. Uncolored selection stays gold; editing stays blue. Reset removes a note's square. Color, completion, and source stay attached to the same ID through promotion, Trash, Restore, and backups.

Plain click selects one item, Command-click toggles an item, and Shift-click selects the inclusive displayed sibling range from the original anchor. Shift with no valid anchor selects only the clicked item; releasing and holding Shift again retains a valid anchor. Edit, color, completion, delete, and Command-N act on the primary selected item. C and Copy Markdown act on the selected visible group. Global search remains single-result selection, and keyboard range selection is deferred. Command+Up/Down outside editors gathers the selected siblings into one displayed-order block at the first selected position, then moves that block one place. Movement clamps to the remaining sibling gaps: a nonadjacent selection can gather at an edge, while an already contiguous edge block stays put. Group dragging inserts the selected items together in source order. One fixed gutter slot supports before/after insertion in the same sibling group, including mixed notes and trees in Root, containers, and Trash. Notes show the grip on hover, selection, or keyboard focus. Trees keep their stack on selection and keyboard focus, swapping it for the grip only during pointer hover. The named Reorder note control remains keyboard reachable with a visible focus ring. The handle also accepts Command+Up/Down and retains focus. Successful sibling reorders move the real cards into place over 300 ms with a decelerating, position-only animation. Reduced motion makes movement immediate and settles any running motion. Scrolling, resizing, hiding, navigation, and a new drag settle cosmetic movement; existing nearest-item visibility still takes priority. Failed or unchanged moves, source edits, membership changes, and search receive no new movement. Already contiguous boundary blocks and unchanged moves are neutral. Owned self, no-op, and background drag positions explicitly reject copying; valid insertion shows move feedback and a guide. Search results cannot be reordered; open their containing tree first. Drags never reparent, accept foreign payloads, or move between scopes. M opens a named modal for cross-parent movement within or between the live library and Trash. Arrows and clicks stage a destination; Enter or Move confirms. Cancel, Escape, and backdrop clicks before submission close it without writing. Self and descendant destinations are excluded. An already submitted move retains its captured intent until acknowledgment or explicit Retry; later selection cannot retarget it. Source flushes before movement, failed metadata actions retry their captured item/color/destination without capturing a draft, and newer navigation or focus retains control. Held Command reveals anchored Search, Root, New tree, Reorder, and Delete hints without moving content.

Saved rendering uses markdown-it with raw HTML disabled. Images become descriptive text and never fetch. JS/TS/JSON fences use Lezer highlighting; other code is escaped. Only explicit HTTP(S)/mailto link activation may open an external application; native validation repeats the frontend scheme/length checks. The narrow native clipboard command writes text only. Neither plugin grants frontend file-opening, shell, clipboard-reading, or general opener permissions.

## Run and verify

Use Node 24.21.0, pnpm 12.4.1, Rust 1.99.1, and the macOS Xcode command-line prerequisites. Direct package and crate versions are pinned; commit both lockfiles when deliberately updating them. Select the required Node and Rust toolchains in your shell before running commands, including Tauri's child commands.

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm tauri:dev
pnpm verify
pnpm tauri:build
```

The frontend owns sibling drag and drop. Keep the native window’s `dragDropEnabled` set to `false` so its file-drop handler does not consume HTML drag events. The editor rejects file drops before editors can import them and cancels unhandled background drops. Ordinary text dropped into an editor stays editable source with Undo/Redo.

`dev` opens the editor with a persistent browser-local development library. Use `tauri:dev` for native file dialogs, window behavior, and Mac acceptance; browser storage is a different profile. The synthetic editor at `http://127.0.0.1:4511/?fixture` uses an in-memory test repository that resets on reload; add `&visual` for fixed public Markdown examples. Fixture modules are development-only and must not enter production assets.

`check` runs Kit type generation, Svelte/TypeScript checks, and formatting. `test:unit` checks policy, validation, reconciliation, and controller ordering. `test:browser` uses strict loopback port 4611 for synthetic editor tests and actual isolated IndexedDB tests; the managed-cloud gate is opt-in and requires a separately approved disposable service. The development server uses port 4511. `build:web` emits static app assets; `build:site` builds the separate landing page. `tauri:build` produces an aarch64 Mac app bundle, without publishing a DMG. Rust tests cover retained native file and window behavior using disposable files. Browser tests do not establish native persistence, actual OTP, IME, or screen-reader acceptance.

Kit 3 config lives in `vite.config.ts`; `src/routes/+layout.ts` disables SSR. The root route opens the persistent Session before mounting the editor and offers Retry on a failed local open, without falling back to an empty library. The static desktop app uses Dexie Cloud for note data and a separate Netlify account-eligibility endpoint before OTP. The [landing page](https://scratchtree.netlify.app) is built from `website/` using `@barbajoe/css-lib`; it is separate from the desktop styling and app assets.

## Accounts and synchronization

Use **Sign in / sign up** at the bottom of the sidebar with a preapproved account. Enter your email, send the code, and then enter the emailed code. Unknown accounts are rejected before requesting an OTP; sign-up is coming later. Sign-out keeps this Mac’s notes available locally and stops cloud transport. A signed-out cold start opens only the local store.

Submitted notes, tree structure/order, colors, completion, and Trash sync. Composer drafts, deletion Undo, editor history, preferences, and recovery remain device-local. Normal online note-source conflicts use last-write-wins. Rejoining after signed-out edits uses a conservative comparison: conflicting remote content is retained, and local alternatives remain recoverable. A different account cannot adopt retained notes. When a Mac has both local and synced notes without an established baseline, a visible decision is required before choosing the synced library.

The right pane distinguishes **Local only**, **Needs sync**, **Syncing**, and **Up to date**. Up to date means the validated local library has matching server evidence, not merely that the connection or login succeeded. Expand it for the last confirmation, Retry, and recovery export. Exported recovered Markdown can be copied into a new note through normal capture; older IDs are not automatically resurrected. If a merged library exceeds capacity, export its full raw recovery before using the explicit correction view. This is synchronization of the current library, not version history or an independent historical backup.

## Persistence and backups

Capture saving is explicit. Capture drafts checkpoint after 300 ms idle; existing-item source commits after the same idle interval without leaving the editor. Pending source flushes before deliberate navigation, export, restore, deletion, and normal close. “Saved” appears only after local IndexedDB acknowledgment. Input typed during a save remains in its own context and is included in the next commit or checkpoint. Failed note saves retain visible source and attempt a recovery checkpoint; retry must succeed before finishing or navigation. Forced termination or power loss can lose input before its checkpoint; window-close failures keep the window open with Retry and hide, Keep window open, or Hide without saving. Hiding without saving retains input in memory, without claiming it reached disk.

Completion waits for the latest source flush, then persists an explicit desired boolean. Repeating the same desired state is a no-op, including its timestamp. A failed source flush or completion write retains the source and completion intent; Editor status offers Retry completion for that exact item and state, without submitting capture.

Delete in the live library retains the complete tree in Trash, with one persistent deletion Undo action. Ordinary Delete records one item; M into Trash records all moved items in source order. One Command-Z restores the whole remaining group atomically to its remembered locations. If a member is separately restored or permanently deleted, the other members remain undoable. Command-Z outside typing controls, text selection, composition, repeat, busy, palette, and modal contexts invokes that same Undo; it never intercepts editor/Search text Undo or Shift-Command-Z, and duplicate pending Undo requests are blocked. Delete inside Trash permanently removes the selected item and its parent-edge children, without Undo or a new safety backup. It does not remove independently detached deleted roots; surviving restore pointers and Undo membership are repaired, and only acknowledged removed items lose their draft/editor caches. This is logical deletion from the current library, not secure erasure of stored data or existing backups. Source flush failure blocks the action and preserves its exact retry intent. Restore uses a remembered live owner, promoting a note if needed, otherwise Root, and clamps the remembered ordinal. Individually restoring an inherited child carries its non-independently-deleted contents to Root. Independent nested deletion records remain in Trash when an ancestor restores. Source buffers, scoped drafts, editor histories, completion, and color survive ordinary promotion, empty demotion, soft deletion, movement, and restoration. Failed actions retain their captured intent without submitting a capture draft or taking newer Search focus. Retained items have no automatic permanent cleanup timer; the minimum 90-day retention excludes explicit user-requested permanent deletion. Parent navigation and search stay within the current live or Trash scope, and restoring an opened tree follows its live location.

The current app uses persistent IndexedDB databases `scratchtree-local-v8` and `scratchtree-cloud-v8` inside its webview profile. A protected local activation record selects the usable copy; these stores are not SQLite bridges. The native identity remains `tech.barbajoe.scratchtree.preview`. Earlier alpha SQLite files are left untouched. Every entry retains its source, identity, metadata, and parent relationship when opened as a tree.

The complete prospective current envelope is validated before replacement or mutation. Unsupported formats, malformed references, and over-capacity data reject without replacing prior notes. Limits are 20,000 stored notes including Trash, 40,002 drafts, 1 MiB UTF-8 per source, and 10 MiB for the complete compact backup. Preserve rejected files and recovery copies. The pending journal and recovery also have explicit bounds; unresolved work is not evicted to make room.

Export uses a native destination dialog and atomic file replacement. BackupV8 is `{format: "scratchtree", version: 8, exportedAt, library: {items, purgedIds}, device: {drafts, undoDeleteIds, recovery}}`. Exact IDs, source, metadata, hierarchy, completion, color, draft revisions, and ordered local Undo are validated. Unknown fields, ambiguous IDs, invalid references, and capacity failures reject before mutation. Restore stages a validated immutable snapshot, shows counts, requires confirmation, and writes a safety file first. While signed in, restore **replaces the shared library on every Mac**, using a new library epoch. Imported device data stays on the importing Mac. Older offline edits are retained for recovery and never silently replayed into the replacement. Cancel is neutral; failure retains the prior copy. Export recovery saves retained alternatives and archived commands. When capacity prevents loading, open Needs sync and choose Export full raw library for the current raw notes and recovery data. If the shared notes exceed their limits, Review raw notes lets you permanently remove selected notes. If only the combined notes, drafts, and recovery exceed local capacity, this Mac preserves its input and can reopen when the shared notes fit. An expired account cache that exceeds capacity offers read-only export for deliberate repair. Recovery exports require repair or conversion before backup import.

Current ceilings are 20,000 items, 40,002 drafts, 1 MiB UTF-8 per source field, and 10 MiB for the complete compact backup envelope. Counts do not guarantee that source and metadata fit the envelope. Each creation intent carries a caller-generated UUID that stays fixed through retry. Matching replay is neutral; conflicting identity rejects without overwrite. After capture failure, a successful authoritative library read may retire the pending request only when its UUID is absent, allowing corrected input to form a new intent. If the item exists or the read fails, the original UUID, source, location, and acknowledgment revision remain fixed for retry; error codes alone do not establish whether the write committed. Parent promotion and child insertion commit together. Reorder is sibling-only; M allows cross-parent movement in either area. Captured before/after group orders support neutral exact replay and reject stale structural intent. Only actually moved roots change content timestamps. Structural rank normalization leaves neighbors' content timestamps unchanged.

Client rendering errors show a readable diagnostic panel and an explicit Reload view control. Submitted notes may already be saved; uncheckpointed input may be lost on reload. Diagnostics retain only a reference, app version, time, error class/status, and sanitized app-module locations. At most three small records stay in browser local storage, with three write attempts per page load; storage failure does not block the panel. Select the displayed details to copy them when reporting a problem. Note contents, raw error messages, arbitrary paths, and query strings are excluded, and nothing is sent to a service.

## Native acceptance

Closing the Mac window (red close control or Command+W) flushes pending edits and hides the application without destroying its window or editor session. Switch back with Command+Tab or click the Dock icon to show that same window, preserving its location, drafts, selection, editor history, and frame. Command+Q and the native Quit menu still fully quit. Direct Quit retains its existing native behavior; input that has not reached its 300 ms checkpoint can be lost, so closing the window first provides the explicit flush safeguard.

The normal native window frame is saved separately in `window-geometry.json` under the Preview app-config directory. Position and dimensions restore after page load; a reachable titlebar permits exact spanning/partial-offscreen placement, while inaccessible placements clamp to available work areas. Minimized, maximized, and fullscreen states reopen normally at the last captured normal frame. Corrupt or unavailable preferences do not block the note library.

Run the packaged `.app` without Vite. Use synthetic notes and native dialogs to check offline reopen, exact Markdown/caret behavior, commands, draft close/reopen, delete/undo, and backup/restore. Confirm keyboard focus, 800×600 reflow at 150% text, and actual IME input separately. The Mac overlay title bar retains real native traffic lights and reserves their space; inspect native dragging/control exclusion, fullscreen entry/exit, and matching titlebar/sidebar colors. Browser fixtures render no imitation native controls. Only the narrow start-drag permission is added; the existing core default supplies native title-region double-click behavior. Browser tests include a synthetic composition event, which does not establish native IME acceptance. Record source/build identity, environment, results, and omissions under an ignored dated `.projects/` folder.

Automated adoption verification does not establish packaged native behavior. Native builds and smoke checks are separate gates; record any unperformed steps explicitly. Use only the Preview profile and synthetic data. Do not access the installed original app, personal stores, or experimental profiles.

Failure tests use isolated IndexedDB, injected public transport interfaces, and temporary native files. The retired SQLite failure-file environment seam is not available. Test-only fixtures do not authorize access to personal profiles or make a browser run native acceptance.

## Boundaries

Domain, search, and rendering policy live in `src/lib/domain`; the controller owns keyed buffers and serialized commands in `src/lib/workspace`; `src/lib/sync` owns the current backup, Dexie Repository, confirmation, Session, and detached reconciliation. The typed Repository boundary stays in `src/lib/platform`. Svelte owns view/CodeMirror lifecycles, and Rust retains narrow platform operations. Public sign-up, version history, automatic updates, mobile, attachments, and Developer ID signing/notarization remain future work. A local save, a connected socket, and successful authentication each differ from independently confirmed synchronization.

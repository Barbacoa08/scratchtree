# Scratchtree

Scratchtree is a local-first Markdown notes app for developers. Capture a thought without leaving the keyboard, write Markdown with its syntax still visible, and keep code snippets, lists, and related notes together in note trees.

Scratchtree supports Apple Silicon Macs in early alpha and offers an experimental Arch Linux x86_64 Preview. The Mac alpha includes private, existing-account Dexie Cloud synchronization. Public sign-up is unavailable. The Arch Preview scope is signed-out local use with disposable notes.

Website and downloads: [scratchtree.barbajoe.tech](https://scratchtree.barbajoe.tech).

## Web editor

The [web editor](https://app.scratchtree.barbajoe.tech/) runs in a regular Chrome or Safari tab on Apple Silicon Macs. Use it to write and organize Markdown notes or try Scratchtree before downloading the Mac app. The free editor stores notes and drafts in this browser profile. After **Ready to reopen offline** appears, you can return to the same address without internet access.

Use **Export backup**, then **Download backup**, to keep a separate BackupV8 file. **Restore backup** previews a local file before replacing the notes in this browser. A restore that exceeds the journal or combined recovery limit leaves the existing notes in place. Clearing browser site data can remove the notes and cached app files. **Check for updates** explicitly connects to the app site. An update saves current edits before switching versions.

## Download and install

### Apple Silicon Mac

**Scratchtree alpha:** the application has its own name, native identity, note-tree terminology, and backup format. The Mac app keeps running when its window closes and returns through Command+Tab or the Dock.

**Alpha compatibility:** version 0.2.8 uses persistent Dexie IndexedDB, BackupV8, and the release identity introduced in 0.2.0. Updating from 0.2.0 through 0.2.7 retains that identity and format. The release uses a separate local profile from earlier alphas and never automatically reads an older store. Before updating from the local-only alpha.5, export and retain its unchanged BackupV7, convert a copy with the separate local transfer tool, and verify the import and a fresh export. Signing in does not transfer those old local notes. Keep the original backup and [previous installer](https://github.com/Barbacoa08/scratchtree/releases/tag/v0.1.0-alpha.5) until the transfer is verified. Breaking changes are expected during alpha.

1. Export a backup before updating, and quit older app copies. The older alpha.5 uses a different backup format: prepare a converted BackupV8 copy before importing it into 0.2.8. See [Transfer from alpha.5](#transfer-from-alpha5) below.
2. Open the downloaded DMG, drag Scratchtree to Applications, and replace the existing app if prompted. Your app data is stored separately from the app.
3. Open Scratchtree from Applications. This alpha is ad-hoc signed, but is not Developer ID signed or notarized, so macOS may block the first launch.
4. If macOS blocks Scratchtree because it can’t verify the developer, click **Done**. Open **System Settings → Privacy & Security**, scroll to **Security**, and choose **Open Anyway** for Scratchtree.
5. Authenticate if prompted, and confirm **Open**.

Only open the app if you trust the download. A managed Mac may restrict this option. [Apple’s illustrated Open Anyway guide](https://support.apple.com/en-us/102445) shows the current Privacy & Security screen.

## Transfer from alpha.5

The BackupV7 converter is a separate maintainer-assisted tool, not part of the app or a public download. Arrange a private conversion with the maintainer before importing an alpha.5 backup. Do not attach notes or backups to public GitHub issues. Keep using the previous installer until the transfer is arranged.

1. Export a BackupV7 from the old app and retain it unchanged, together with the old installer. Convert a copy to BackupV8 through that private transfer process; do not import BackupV7 directly into 0.2.8.
2. Open 0.2.8 and sign in to the account that should own the notes. Signing in alone does not transfer the older local library.
3. Choose **Restore backup**, select the converted BackupV8, review the counts, and confirm only when ready. **Restore replaces the current library; while signed in, it replaces the shared library on every Mac.** It does not merge the backup into existing notes.
4. Wait for **Up to date**, check the notes, and export a fresh BackupV8. Keep the original export and recovery installer until both the transfer and the second-Mac copy are verified. Drafts and Undo import only on this Mac.

## Get started

Paste this Markdown into the composer at the bottom, then press Enter to save.

```markdown
**Release checklist**

- Verify offline editing
- Check keyboard shortcuts
- Update the download notes
```

- Select your checklist and press L to assign a color. The gutter keeps the color visible as you hover and edit.
- Select a note and press E or double-click to edit it. Press Enter outside fenced code or Escape to finish editing and keep changes.
- Press Command+N to write inside the selected note, or write here when nothing is selected. Enter/Right opens a selected item. Use the breadcrumb, Back/Forward controls, or mouse side buttons to navigate.
- Press Command+F to search, X to toggle completion, and V to toggle each selected long note’s preview. Command-click adds or removes selections, Shift-click selects a range, and Shift+Up/Down extends its edges. Drag or Command+Up/Down rearranges selected siblings, and M opens the move destination dialog.
- On macOS, export backups from the app to keep a separate copy of your library. Trash retains deleted items and supports restoring them.

The sections below describe the current source. Its stack is SvelteKit static output, Svelte, CodeMirror, Tauri, persistent Dexie IndexedDB, and Dexie Cloud. Native code provides file dialogs, atomic backup files, window behavior, clipboard, and external links. Root is the always-visible top of the live library. Its small Flowing Roots icon and separator distinguish it from the child trees below; it has no expand/collapse control. Other functional icons retain their existing appearance.

## Appearance

Use the three-part **Appearance** control at the bottom of the sidebar: **Light** (sun), **System** (computer), and **Dark** (moon). System is the default and follows your Mac's appearance, including changes while Scratchtree is open. An explicit choice is remembered on that device. Use Tab to focus the selected option, arrow keys to change it, and Tab to leave the group. Appearance is separate from your note library and backups; changing it keeps unfinished Markdown and editor Undo history. These controls are included in 0.2.0.

## Capture and edit

Outside fenced code, Enter saves, Shift+Enter adds a line or continues a list, and Command+Enter also saves. Inside a fenced code block, all three insert a code line; move outside the fence to save with Enter, or use Save note. Opening and closing delimiter lines count as code, and an unclosed fence stays code through the end of the source. Empty captures are rejected, and the composer clears only after acknowledgment. Markdown delimiters remain visible while strikethrough, emphasis, all six distinct heading levels, lists, and code are styled. In saved notes, a single Markdown line break renders as a new line. Adjacent paragraphs and list items use the same spacing. Command+B and Command+I toggle bold and italic on the actual source. A selection stays selected inside the new markers; an empty caret inserts paired markers, or removes its enclosing style when already formatted. Bold and italic combine, and removing one keeps the other. Formatting leaves inline and fenced code unchanged, and ambiguous partial delimiter selections are left untouched. Each command is one Undo step. Standard copy, paste, selection, and undo operate on the actual source. LF, CRLF, and mixed source separators remain intact through edits and undo. New typed line breaks use the existing first separator, or LF when the document has none. Raw paste/input separators are retained when the browser exposes them; OS clipboard conversion remains a platform limit.

Typing the third opening backtick on an otherwise empty plain line, with zero to three leading spaces and one caret at its end, immediately adds a matching closing fence on the next line. A single typed input containing exactly three backticks also works. The caret stays after the opening ticks for language-info typing; Enter then inserts the body line before the closer. The triggering input and generated closer undo and redo atomically, using normal editor history and Redo caret behavior. Consecutive extra backticks extend only that newly generated pair; moving the caret or typing anything else ends that pairing ownership. Existing valid closers, direct inputs of four or more ticks, pasted/dropped text, selected text, multiple carets, composition, read-only input, inline code, existing fenced code, list/quote contexts, and tilde fences receive no automatic pair. Existing source bytes and separators stay intact. The drawn caret retains normal blinking and its full stroke at blank and start-of-line positions inside the editor scrollport.

Single click selects a card. Double click, Edit, or E opens inline editing for either kind of item. E places the caret at the source end every time, including cached edits; pointer editing retains the cached caret. Existing-item edits save after 300 ms idle. Outside fenced code, Enter finishes editing; Escape always finishes editing. Both keep changes and leave the same note selected for immediate E. Clicking away saves and exits while preserving the new target and focus. Navigation flushes the latest visible source. Saved notes with more than five rendered text lines default to a one-line preview with a full-width Expand/Collapse bar and one trailing directional chevron; expanded bodies grow up to 48rem and then scroll internally. Expansion follows each exact note ID for this editor session and survives promotion, soft deletion, and Undo, and resets after full backup replacement. Inline editing enters at the rendered body’s footprint, including when raw links or fence markers are taller. Changing the source lets the editor grow from that baseline to the current cap, then scroll internally; autosave preserves the grown editor, caret, and history. Emptying an existing note keeps its identity and ownership; deletion is explicit. The shortcut reference retains the selected note’s most recent editing context after finishing, and clears it when selection changes or the library is restored. Root, Trash, and each tree have independent capture drafts and cached editor history. Composer and inline drafts are independent; Escape from the composer preserves its text and the prior highlight, and focuses the stream. Up with one empty caret at source offset zero returns to the highlighted visible item, or falls back to the last visible note when there is no highlight, and focuses the stream while preserving the draft, caret, history, and search query. When no entries are displayed, Up or Left at source offset zero with one empty caret focuses the note stream, as Escape does; another Left opens the parent tree. The draft, caret, history, and search query stay intact. Left keeps ordinary editor behavior when entries are displayed, and Up does the same for a tree-only stream with no highlight. Search filters saved source globally and case-insensitively, shows each result’s owning path, keeps the capture destination visible, and labels any active edit outside the results. Sidebar navigation clears search; editing a search result preserves its query and the current capture destination. Search includes saved tree source. Root search excludes effectively deleted trees; Trash search searches only trashed saved source; its created-time/ID order is separate from sibling order.

Command+N enters the valid selected visible item, including an inline edit or search result, and focuses its composer without creating a child. A selected note becomes a tree while retaining its exact ID, source, completion, color, parent, and position. With no selection, Command+N focuses the current composer, like Space. Leaving a tree with no saved children turns it back into a note, preserving its source, identity, and composer draft. Enter/Right can open it again; history skips destinations that are no longer trees. Clicking blank stream background safely flushes an active edit and clears the selection. Clicking the text area of the composer focuses it, and Escape preserves the prior note highlight. Containers have ordinary source editing, copy, completion, and deletion actions; there is no Rename dialog or separate trimmed name field. Empty existing source remains valid. Sidebar and location labels use bounded source previews, and deep rows retain limited indentation and their actual level.

Space outside controls focuses capture. Command+/ or Command+F focuses search from editors or the stream; / also focuses search outside controls. Command+1 opens Root after flushing the latest source. Command+2 through Command+9 opens the first eight visible direct-child trees of Root in sidebar order. Completed trees and their descendants are hidden from the sidebar, but remain in the stream and search. Hold Command to reveal anchored Search, Root, and tree-number hints without moving content or focus; Escape clears search and focuses the stream. Up/Down selects cards. Enter/Right opens any selected stream item, promoting a note while preserving its identity and source. Empty destinations focus the composer; nonempty destinations restore the last valid selection or select their first entry with stream focus. Left outside controls opens the parent and selects the tree just exited. Double click edits source. X marks all selected items done if any are incomplete, or clears completion if they are all done. With the note stream focused, V flips each selected long note’s preview independently: expanded notes collapse and collapsed notes expand. Short notes are unchanged. Completed items stay searchable, use subdued strike-through in saved rendering, and remain legible while editing. The Mark done toggle keeps its accessible name, exposes its pressed state, and changes its tooltip to describe the next action. Held X, modifiers, composition, text selection, and typing controls do not toggle completion. E edits at the source end, C copies all selected visible notes in displayed order with one newline between their exact Markdown sources, and Command+Backspace deletes the selected items without confirmation. Copy Markdown uses the same group, includes a selected tree’s own source without its children, and uses the active source buffer when applicable. Deletion selects the successor at the first removed visible ordinal, otherwise the previous item, otherwise the composer. Single-letter shortcuts leave text inputs, selection, composition, and confirmations alone. Copy failure is shown without changing source. M moves selected siblings to an eligible tree, Root, or Trash. Moving from the live library into Trash creates one undoable group; moving back restores the selected items at the chosen destination and keeps independently deleted descendants in Trash.

The unified title strip contains Back/Forward session history and a clickable breadcrumb. Mouse side buttons Back/Forward use that same app history once on release, including over editors; their URL-history default is consumed at boundaries and while blocked. History retains up to 100 acknowledged visits, including distinct Root and Trash roots. A new visit after Back replaces the forward branch; failed navigation does not move the cursor, and a successful captured Retry records or completes its original visit. Missing trees and entries whose recorded live/Trash scope has changed are skipped. Structural deletion/restoration reconciles the current slot, and full backup replacement resets the session history. History and breadcrumb navigation flush source and never promote a note. The breadcrumb shows the scope root, at most the last two source previews, and an omitted-ancestor count for deeper paths; Trash ancestry stops at the explicit deleted root. Left remains available for successive parent navigation within the current scope.

Show/Hide Details works at every width. Before a deliberate choice, Details is shown on wide windows and hidden at 1050px or narrower; a session choice survives later resizing. Collapsing releases the wide column, removes the rail from keyboard and accessibility navigation, and moves focus from its contents to the toggle. Expanding on resize retains Search/editor focus. Editor status and its local-save explanation remain at the bottom of expanded Details. While collapsed, normal status remains announced without occupying space. With confirmed sync, open Details and expand Up to date to see the retained recovery count and export options. Errors, bounded color context, and captured Retry controls appear in a compact scrollable panel at the lower right. The panel does not change editor geometry. A simultaneous failed palette has separate scroll space so its controls and pointer Retry remain reachable.

L outside typing controls opens Assign color for the selected item; Details also exposes Assign color. The named nonmodal palette contains a two-column layout grid of nine fixed-color swatches and an icon-only Reset. Names remain accessible to assistive technology. One tooltip shows the hex value and color name beside the active column, outside the swatches; the latest pointer or keyboard action owns it. Arrow keys stage a choice by row and column without changing the saved color; boundaries stop, Home/End move within a row, and the pressed state and check mark identify the saved color. Enter, Space, or clicking applies the exact choice once and closes after acknowledgment. Escape, outside focus/pointer, and Tab dismiss an unsubmitted or failed choice without writing; pending dismissal requests leave the picker visible while external controls remain usable. Failure retains the exact item and color for Retry action, with bounded item context in Editor status. Successful retry only closes its own session and never takes newer Search focus. There is no Done button. An assigned color appears in the card’s left gutter. Idle notes show a vertical line. The tree icon and grab handle share a gutter slot. A line continues below the icon or handle on multiline cards and beside Expand or Collapse on long notes and trees. Hovering a tree swaps its icon for the colored handle. The assigned color also outlines selected cards, and the editor keeps its blue focus outline. Uncolored selection stays gold. Reset removes the assigned color. Color, completion, and source stay attached to the same ID through promotion, Trash, Restore, and backups.

Plain click selects one item, Command-click toggles an item, and Shift-click selects the inclusive displayed sibling range from the original anchor. Shift with no valid anchor selects only the clicked item; releasing and holding Shift again retains a valid anchor. Shift+Up adds the sibling above the top selected item, and Shift+Down adds the sibling below the bottom selected item. Edit, color, card completion and delete buttons, and Command-N act on the primary item. X, Command+Backspace, C, and Copy Markdown act on the selected visible group. Global search uses single-result selection. Command+Up/Down outside editors gathers the selected siblings into one displayed-order block at the first selected position, then moves that block one place. Movement clamps to the remaining sibling gaps: a nonadjacent selection can gather at an edge, while an already contiguous edge block stays put. Group dragging inserts the selected items together in source order. One fixed gutter slot supports before/after insertion in the same sibling group, including mixed notes and trees in Root, containers, and Trash. Notes show the grip on hover, selection, or keyboard focus. Trees keep their tree icon on selection and keyboard focus, swapping it for the grip only during pointer hover. The named Reorder note control remains keyboard reachable with a visible focus ring. The handle also accepts Command+Up/Down and retains focus. Each keyboard tap updates the visible order immediately. The order saves after 400 ms of quiet, with a maximum 1,000 ms delay before an available save starts. Navigation, closing the window, and backup actions flush the order. If saving fails, Editor status offers Retry reorder for the captured order. Keyboard reorders animate the projected order and dragging animates the acknowledged order over 300 ms with a decelerating, position-only animation. Reduced motion makes movement immediate and settles any running motion. Scrolling, resizing, hiding, navigation, and a new drag settle cosmetic movement, and existing nearest-item visibility still takes priority. Unchanged moves, source edits, membership changes, and search receive no new movement. Already contiguous boundary blocks and unchanged moves are neutral. Owned self, no-op, and background drag positions explicitly reject copying; valid insertion shows move feedback and a guide. Search results cannot be reordered; open their containing tree first. Drags never reparent, accept foreign payloads, or move between scopes. M opens a named modal for cross-parent movement within or between the live library and Trash. The move dialog initially focuses Search destinations, which filters names and paths. Tab moves through the dialog controls. Down from search focuses the first result, and Up from the first result returns to search. Arrows and clicks in the list highlight a destination. Enter from search or the results and the Move button confirm the highlighted destination. Cancel, Escape, and backdrop clicks before submission close it without writing. Self and descendant destinations are excluded. An already submitted move retains its captured intent until acknowledgment or explicit Retry; later selection cannot retarget it. Source flushes before movement, failed metadata actions retry their captured item/color/destination without capturing a draft, and newer navigation or focus retains control. Held Command reveals anchored Search, Root, tree-number, Write a note, Reorder, and Delete hints without moving content.

Saved rendering uses markdown-it with raw HTML disabled. Images become descriptive text and never fetch. JS/TS/JSON fences use Lezer highlighting; other code is escaped. Each fenced or indented code block has a Copy code button that copies only its code, including blank lines and indentation, without fences or line numbers. Only explicit HTTP(S)/mailto link activation may open an external application; native validation repeats the frontend scheme/length checks. The narrow native clipboard command writes text only. ## Accounts and synchronization

Use **Sign in / sign up** at the bottom of the sidebar with a preapproved account. Enter your email, send the code, and then enter the emailed code. Unknown accounts are rejected before requesting an OTP; sign-up is coming later. Sign-out keeps this Mac’s notes available locally and stops cloud transport. A signed-out cold start opens only the local store. If code verification or initial sync takes five seconds, Close becomes available so you can return to local work. Closing pending verification cancels that attempt; a late response cannot adopt the online library. A submitted library change may still finish after the dialog closes, and the recovery message explains that distinction.

Submitted notes, tree structure/order, colors, completion, and Trash sync. Composer drafts, deletion Undo, editor history, preferences, and recovery remain device-local. Normal online note-source conflicts use last-write-wins. Rejoining after signed-out edits uses a conservative comparison: conflicting remote content is retained, and local alternatives remain recoverable. A different account cannot adopt retained notes. On first sign-in with both local and synced notes, review the counts and choose **Merge notes**. Distinct notes from both libraries are combined. If the same note exists in both, the version with the later saved edit time wins, with the synced version kept on a tie. Scratchtree saves a local safety backup before merging.

The right pane distinguishes **Local only**, **Needs sync**, **Syncing**, and **Up to date**. Up to date means the validated local library has matching server evidence, not merely that the connection or login succeeded. Expand it for the last confirmation, Retry, and recovery export. Exported recovered Markdown can be copied into a new note through normal capture; older IDs are not automatically resurrected. If a merged library exceeds capacity, export its full raw recovery before using the explicit correction view. This is synchronization of the current library, not version history or an independent historical backup.

## Persistence and backups

Capture saving is explicit. Capture drafts checkpoint after 300 ms idle; existing-item source commits after the same idle interval without leaving the editor. Pending source flushes before deliberate navigation, export, restore, deletion, and normal close. “Saved” appears only after local IndexedDB acknowledgment. Input typed during a save remains in its own context and is included in the next commit or checkpoint. Failed note saves retain visible source and attempt a recovery checkpoint; retry must succeed before finishing or navigation. Forced termination or power loss can lose input before its checkpoint; window-close failures keep the window open with Retry and hide, Keep window open, or Hide without saving. Hiding without saving retains input in memory, without claiming it reached disk.

Completion waits for the latest source flush, then persists an explicit desired boolean. Repeating the same desired state is a no-op, including its timestamp. A failed source flush or completion write retains the source and completion intent; Editor status offers Retry completion for that exact item and state, without submitting capture.

Delete in the live library retains the complete tree in Trash, with one persistent deletion Undo action. Ordinary Delete records one item; M into Trash records all moved items in source order. One Command-Z restores the whole remaining group atomically to its remembered locations. If a member is separately restored or permanently deleted, the other members remain undoable. Command-Z outside typing controls, text selection, composition, repeat, busy, palette, and modal contexts invokes that same Undo; it never intercepts editor/Search text Undo or Shift-Command-Z, and duplicate pending Undo requests are blocked. Delete inside Trash permanently removes the selected item and its parent-edge children, without Undo or a new safety backup. It does not remove independently detached deleted roots; surviving restore pointers and Undo membership are repaired, and only acknowledged removed items lose their draft/editor caches. This is logical deletion from the current library, not secure erasure of stored data or existing backups. Source flush failure blocks the action and preserves its exact retry intent. Restore uses a remembered live owner, promoting a note if needed, otherwise Root, and clamps the remembered ordinal. Individually restoring an inherited child carries its non-independently-deleted contents to Root. Independent nested deletion records remain in Trash when an ancestor restores. Source buffers, scoped drafts, editor histories, completion, and color survive ordinary promotion, empty demotion, soft deletion, movement, and restoration. Failed actions retain their captured intent without submitting a capture draft or taking newer Search focus. Retained items have no automatic permanent cleanup timer; the minimum 90-day retention excludes explicit user-requested permanent deletion. Parent navigation and search stay within the current live or Trash scope, and restoring an opened tree follows its live location.

The current app uses persistent IndexedDB databases `scratchtree-local-v8` and `scratchtree-cloud-v8` inside its webview profile. A protected local activation record selects the usable copy; these stores are not SQLite bridges. The permanent release identity is `tech.barbajoe.scratchtree`. It starts a separate profile from earlier Preview builds; signing in uses the same account library after any required join decision, while device-local drafts and settings stay in their original profiles. Signing in does not upload notes from the older local-only app. Earlier alpha SQLite files are left untouched. Every entry retains its source, identity, metadata, and parent relationship when opened as a tree.

The complete prospective current envelope is validated before replacement or mutation. Unsupported formats, malformed references, and over-capacity data reject without replacing prior notes. Limits are 20,000 stored notes including Trash, 40,002 drafts, 1 MiB UTF-8 per source, and 10 MiB for the complete compact backup. Preserve rejected files and recovery copies. The pending journal and recovery also have explicit bounds; unresolved work is not evicted to make room.

Export uses a native destination dialog and atomic file replacement. BackupV8 is `{format: "scratchtree", version: 8, exportedAt, library: {items, purgedIds}, device: {drafts, undoDeleteIds, recovery}}`. Exact IDs, source, metadata, hierarchy, completion, color, draft revisions, and ordered local Undo are validated. Unknown fields, ambiguous IDs, invalid references, and capacity failures reject before mutation. Restore stages a validated immutable snapshot, shows counts, requires confirmation, and writes a safety file first. While signed in, restore **replaces the shared library on every Mac**, using a new library epoch. Imported device data stays on the importing Mac. Older offline edits are retained for recovery and never silently replayed into the replacement. Cancel is neutral; failure retains the prior copy. Export recovery saves retained alternatives and archived commands. When capacity prevents loading, open Needs sync and choose Export full raw library for the current raw notes and recovery data. If the shared notes exceed their limits, Review raw notes lets you permanently remove selected notes. If only the combined notes, drafts, and recovery exceed local capacity, this Mac preserves its input and can reopen when the shared notes fit. An expired account cache that exceeds capacity offers read-only export for deliberate repair. Recovery exports require repair or conversion before backup import.

## Boundaries

Domain, search, and rendering policy live in `src/lib/domain`; the controller owns keyed buffers and serialized commands in `src/lib/workspace`; `src/lib/sync` owns the current backup, Dexie Repository, confirmation, Session, and detached reconciliation. The typed Repository boundary stays in `src/lib/platform`. Svelte owns view/CodeMirror lifecycles, and Rust retains narrow platform operations. Public sign-up, version history, automatic updates, mobile, attachments, and Developer ID signing/notarization remain future work. A local save, a connected socket, and successful authentication each differ from independently confirmed synchronization.
